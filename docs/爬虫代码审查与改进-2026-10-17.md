## 一、总体结论

提交版本是一个**能跑通的可用原型**：WBI 签名、分页游标、楼中楼、rpid 去重、
断点续爬、BV 号解析这些核心链路实现正确，代码风格统一、错误信息可读，
作为课程项目的第一次爬虫提交质量合格。

但它更接近「一次性脚本」，在**合规（robots/来源登记）、反爬稳健性、数据标准化、
可复用接口、可观测性**五个方面存在明显缺口；其中合规项与课程验收要求直接冲突
（README 已宣称遵守 robots，但代码没有实现，对应 Issue #4）。

## 六、审查中发现的两个反爬细节（实测）

1. **buvid3 会收紧匿名评论配额**：同一接口、同一 UA，不带 buvid3 时首页返回
   19 条且可继续翻页；带上 buvid3/buvid4 后只返回 3 条且 `is_end=true`。
   因此改进版默认**不**自动初始化 buvid，仅保留 `BILI_INIT_BUVID=1 / --init-buvid`
   显式开关（用于确实需要设备指纹的场景）。
2. **robots.txt 的 Cookie 污染**：用同一个 `requests.Session` 请求
   `www.bilibili.com/robots.txt` 会收到 `buvid3` cookie，随后 API 评论配额被限制为
   3 条。改进版为 robots 检查使用**独立会话**，避免合规检查反而改变业务会话状态。
