## 一、前端修复

### 1. 单条预测页置信度条不可见

- **现象**：页面给出「正面 / 负面」与置信度百分比，但两条进度条一直是空轨道（用户报「进度条没变化」）。
- **根因**：`frontend/src/assets/main.css` 的 `.prob-row__fill` 作用于 `<span>`，但规则里没有
  `display: block`；内联元素忽略 `width` 百分比，实测 `getBoundingClientRect().width === 0`。
- **修复**：`frontend/src/assets/main.css` 为 `.prob-row__fill` 增加 `display: block`、为
  `.prob-row__bar` 增加 `min-width: 0`（grid 压缩场景保险）。
- **验证**：Playwright 实测 `3.17% → 10.52px`、`96.83% → 321.47px`（轨道 334px）；
  截图 `outputs/e2e/_final_predict_bars.png`。
- **回归测试**：`frontend/tests/prob-bars.test.js`（Node 内置 `node:test`，4 条，零新依赖）。

### 2. 二分类模型下仍渲染「中性」

- **现象**：模型只有 positive/negative，但已完成视频详情显示「中性 0.0%」并把 0 值扇区画进饼图，
  趋势图固定三条线。
- **根因**：`SentimentPie.vue` / `TrendLine.vue` 硬编码三类；后端契约保留 `neutral` 字段（恒为 0）。
- **修复**：新增 `frontend/src/utils/sentimentSeries.js`（纯 ESM 纯函数）：
  positive/negative 恒展示；neutral 仅在计数或比例非零时展示；缺失/非数字按 0 处理不抛错。
  `SentimentPie.vue`（饼图 data、图例、比例行）与 `TrendLine.vue`（series）统一由它驱动。
  三分类/回退数据 `neutral > 0` 时仍照常显示。
- **验证**：完成页只剩「正面 37.5% / 负面 62.5%」，页面文本不含「中性」；
  页面内构造 `neutral=3` 后三类恢复显示。截图 `outputs/e2e/_final_neutral_hidden.png`。
- **回归测试**：`frontend/tests/sentimentSeries.test.js`（8 条）。

### 3. 误导性「待接入后端 / 骨架阶段」文案

- **现象**：单条预测页只要还没点预测就显示「待接入后端：…请先启动 FastAPI 服务…骨架阶段」，
  即使后端已连接；任何错误（400/超时）都被归因成「未接入」。批量预测、模型对比页有同类残留。
- **修复**：新增 `frontend/src/utils/requestError.js`（`isConnectionError` / `backendHintFor`）；
  `SinglePredictView.vue`、`BatchPredictView.vue`、`ModelCompareView.vue` 统一语义：
  空闲态中性引导（「等待预测 / 等待上传」），错误态「<操作>失败：<原因>」，
  只有连接类失败（无法连接 / fetch failed / network / HTTP 5xx）才追加启动后端命令，且与
  `api/client.js` 自带提示去重。`HomeView.vue` 是未挂载的历史骨架页，保留未改。
- **验证**：Playwright 断言三页均无「待接入后端」「骨架阶段」；网络失败/HTTP 400/500 文案分支正确。

### 4. Windows 启动脚本

- **现象**：仓库没有 `.venv`，但 `start-backend.cmd` 硬编码 `.venv\Scripts\python.exe`，
  双击立即退出（用户会误以为后端不可用）。
- **修复**：`start-backend.cmd` 优先使用 `.venv`，缺失时回退系统 `python`；缺 `uvicorn/fastapi`
  时打印安装指引而不是闪退。`start-frontend.cmd` 在缺少 `node_modules` 时自动 `npm install`。

## 二、真实采集：账号 Cookie 受限时匿名回退

- **现场**：`outputs/settings.json` 的账号 Cookie 经 `login_status()` 仍返回「已登录」，
  但用同一 Cookie 请求评论接口返回 `replies=[]` 且 `cursor.is_end=false`（被限制/风控）；
  匿名请求同视频可正常返回。旧行为：任务约 8 秒后 `failed`（「当前页没有评论，但未收到结束标记
  （可能被风控）」），前端停在 0%，用户以为「爬虫接口没接到前端、看不到爬取进度」。
- **修复**（`src/videos/crawler_adapter.py`）：带 Cookie 首次采集若异常链命中
  `当前页没有评论` / `未收到结束标记` / `风控` / `风险控制` / `HTTP 412` / `HTTP 429` /
  `-352` / `-509`，用同一内容参数（仅 `cookie=None`、`require_login=False`）**单次**回退匿名采集；
  成功返回记录并写 warning（Cookie 已脱敏），两次都失败才抛
  `CrawlAdapterError`，提示「重新登录 / 关闭必须登录改用匿名 / 稍后重试」。
  无 Cookie、占位与其它失败路径行为不变；`on_page` 进度回调照常，前端可看到
  「正在爬取评论… 已完成 N 页，已采集 M 条」。
- **验证**：同一失败任务重试 + 新任务实测均成功（账号模式 → 11.8 秒完成采集，进度 0→40%、
  条数实时更新；浏览器复验显示「1 条 · 20%｜正在爬取评论… 已完成 1 页，已采集 1 条」）；
  任务索引与错误信息中无 Cookie 明文。
- **回归测试**：`tests/test_videos_real_crawl.py` 新增 7 个离线用例（回退成功/双失败/非风控不回退/
  无 Cookie 只调一次/分步流水线端到端），全部 mock 不触网。

## 三、仓库评论数据清理

- **动机**：GitHub 仓库约 74 MB（本地 `.git` 约 95 MB），其中评论数据文件占绝大部分，与代码无关。
- **处理**：`git rm --cached` 移除 **490 个文件 / 94.82 MB** 的跟踪（**本地文件全部保留**）：
  - `data/raw/` 459 个（3 个 BV 评论 CSV、公开语料 CSV、`sentiment_crawl/` 分片/断点/日志）；
  - `data/processed/` 5 个大 CSV、`data/splits/` 6 个 CSV+NPZ；
  - `outputs/realdata/` 14 个、`outputs/videos/` 6 个运行期任务 JSON。
  保留：各级 README / 来源登记 / `data/sample/` 格式样例 / `data/processed` 小 JSON
  （词表、预处理配置、manifest，推理与训练直接读取）/ `models/` 权重 / `outputs/figures/` 图表。
- **结果**：Git 跟踪体积 **141.48 MB → 46.70 MB**（剩余 data+outputs 66 文件 / 2.24 MB，
  models 40.88 MB 保留）。
- **配套**：`.gitignore` 修正（删除已失效的 `!BV1tseyzCEoF_comments.csv` 例外、sentiment_crawl
  改为「只保留 README」、显式反忽略 processed 小 JSON）；`data/README.md`、`data/raw/README.md`、
  `data/processed/README.md`、`data/splits/README.md`、`outputs/README.md` 重写为「不入库 + 本地保留 +
  重新生成命令」；根 README 第 3/4/7/8 节同步。
- **仓库瘦身与历史**：`git rm --cached` 只让**当前提交**不再包含这些文件；历史提交里的旧 blob 仍在，
  因此 GitHub 仓库体积不会立即下降。要真正清除需改写 Git 历史（`git filter-repo`/BFG）并
  `force push`，会影响所有分支与协作者，本轮未执行，需仓库所有者确认后单独操作。
