# 实时进度显示与验证

原先真实采集同步返回后才更新评论数，清洗和分析完成后再推进计时进度。
页面即使轮询，也只能长时间看到同一快照。统计汇总还会再预测一次全部评论。

## 现在的行为

- 爬虫入口透传已有的 `on_page`，视频适配层在每页完成时更新累计页数及评论数。
  网络请求前即进入 crawling；采集完成才到 40%，不会采集结束后再从 0 模拟增长。
- 分步清洗、分析在实际循环中报告 `done/total`，按整数进度变化或 250ms 间隔写入，
  同时检查关停信号与任务代次。空文本、重复项同样计入已处理数量。
- 汇总使用本轮预测，标签和置信度与 `analyze.json` 一致；详情保存后才到 completed / 100%。
- 前端每秒更新列表及选中详情，侧栏和大进度块显示实时条数与阶段说明。
  终态/等待态停止轮询，继续任务恢复；旧等待态详情与列表不一致时仍追到新状态。
  同一任务的过期详情响应会被丢弃，避免慢响应覆盖新进度。
- 复用现有字段，不新增端点或运行依赖；原始评论展示及历史关键词过滤修复均保留。

采集百分比是按页数/条数上限换算的阶段估算，并非视频全量评论的完成比例。
每页网络请求与楼中楼处理期间可能暂时保持同一个百分比；实际采集页数/条数是确定值。
未获得视频总评论量时不编造总量或剩余时间。占位数据仍按配置时长运行，便于离线展示。
