# 第二轮全面改进与集成测试（2026-10-17）

> 起点：`main @ 3738b68`（第一轮爬虫重构后的状态）。
> 方式：Lead 设计任务与写入边界，3 个 Subagent 并行实现；Lead 统一集成、补强、测试与提交。
> 结果：第二轮结束时全量 **451 passed**；后续「大规模采集」补强后当前 **460 passed**（新增 9 条），
> 真实 `/api/videos` 联网冒烟通过；公开语料闭环 `course_requirements_met=true`；详见根 README 第十二节。

## 一、为什么做第二轮

第一轮把爬虫本身做到了「合规、可恢复、可复用、可观测」，但评估后仍有三块短板直接影响课程交付：

1. **数据规模与标注**：匿名爬虫可见评论有限（39/237738），`data/` 仍缺训练 ≥8000 / 测试 ≥2000 的语料；
2. **链路没接完**：`/api/videos` 的「采集评论」仍是占位，界面上的真实分析体验不完整；
3. **长跑边界条件**：输入 BV 不去重、楼中楼分页写死 20、中断后楼中楼重复请求、无时间预算。

## 三、交付内容

### 1. 公开数据集获取（`src/crawler/datasets.py`）

- 注册表 4 条公开中文语料：ChnSentiCorp（酒店，约 7.7k）、外卖评论（约 1.2 万）、
  酒店评论、购物评论；含 license / note / 原始列名提示；
- `download_dataset(name, target_dir, timeout, force)`：标准库 urllib 流式下载 →
  `.part` 临时文件 → 可选 SHA256 校验 → `os.replace` 原子改名 → 自动
  `sources.register_source` 登记（记录实际 SHA256、条数、许可）；
- `import_labeled_csv(...)`：统一为 `text,label`（UTF-8 BOM），标签映射覆盖
  `0/1`、`pos/neg`、`正面/负面`、`好评/差评`，去空、按文本签名去重；
- CLI：`python -m src.crawler.datasets --list/--download/--import-csv`；
- **Lead 补强**：URL 仅允许 `http(s)`、`filename` 拒绝目录穿越（防止 `file://` 读本机文件）。

### 2. 标注工作流（`src/crawler/labeling.py`）

- `export_labeling_sample`：按 `video_id`/`bvid` 分层、固定 seed、最大余数法分配名额，
  排除已标注/重复文本/空文本，输出 `id,text,group,video_id,label(空)` + manifest
  （输入/输出 hash、分组统计、排除原因、seed）；
- `merge_labels`：校验标签取值、重复 id、同 id 冲突、缺失/空 id；strict 失败不写输出，
  非 strict 跳过并记录 excluded；输出 accepted / label_counts / hash manifest；
- CLI：`python -m src.crawler.labeling export|merge`。

### 3. 爬虫长跑稳健性（`src/crawler/bilibili.py`）

- `crawl_bilibili` 对输入 BV 按顺序去重（非法 BV 仍逐条记录错误）；
- 新增 `SUB_COMMENT_PAGE_SIZE=20`，`get_sub_comments` 显式传 `ps`；结束判断改为
  `page.count/page.size` 自适应，`count` 缺失时用短页推断，`max_sub_pages` 兜底；
- state 新增 `sub_done`：恢复时跳过已完整处理的根评论楼中楼；旧断点兼容；
  整页推进后清空以控制 state 体积，防御上限 5000 条；
- 新增 `--max-seconds` 时间预算：页间 / 根评论间检查，到时先落 CSV 再存断点；
  `VideoCrawlResult.timed_out` 与 `CrawlReport.timed_out` 进入报告；默认 0 = 不限；
- 默认行为零变化，原有 60 条测试全部保留。

### 4. `/api/videos` 真实爬取（opt-in）

- 新增 `src/videos/crawler_adapter.py`：`VideoCrawlConfig`、`collect_video_comments`
  （默认延迟导入 `src.crawler.fetch_video_comments`，支持注入 fetcher）、`CrawlAdapterError`；
- `PipelineConfig` 增加 `real_crawl` 与 `crawl_max_pages / crawl_max_items /
  crawl_delay_seconds / crawl_include_replies / crawl_timeout`，全部由 `VIDEO_CRAWL_*`
  环境变量驱动，非法值回退默认；
- 流水线：`real_crawl=True` 时在「采集评论」阶段真实采集，真实条数作为 `comment_count`，
  失败写 `failed`（带可读 error）并抛 `PipelineFailure`，不会卡在 `crawling`；
  真实采集已消耗真实时间，**不再额外 sleep 12 秒的模拟采集时长**（Lead 集成修正）；
- `placeholder.build_detail(comments=...)`：真实评论时生成真实 `comment_total`、
  `top_comments`（按点赞）、`keywords`（jieba 词频）、`trend`（按 `ctime_utc` 天分桶）、
  `length_stats`，`placeholder=false`；默认 `comments=None` 输出与旧版逐字段一致；
- 情感极性使用 `predict_rule_based`（规则占位），`method=rule_placeholder` 诚实标注；
- Lead 补强：关键词过滤 URL/域名/`@提及`/`[B站表情]` 噪声（真实冒烟中发现词云出现
  `https/com/bilibili/share/music`）。

### 5. 效率基准增强（`scripts/bench_crawler.py`）

- 离线默认 `--repeat 3`，报告中位数与 min/max；
- 记录进程 RSS（`psutil` 可选，未安装则跳过）；
- 保留离线 mock 的 WBI 校验 / 分页 / 楼中楼 / 412 风控恢复注入。

## 六、已知风险与未覆盖

1. 公开数据集内置 URL/SHA256 未联网验证（任务要求测试不联网）；首次下载前建议实际跑一次并复核；
2. 数据集 ZIP 只下载不解压，`import_labeled_csv` 只收 CSV（当前 4 个内置语料均为 CSV）；
3. 匿名账号可见评论仍有限，完整语料需登录态；真实模型未接入，情感仍为规则占位；
4. `src/artifacts` 的上传链路仍未接真实爬取（本次只接 `/api/videos`）；
5. 时间预算测试依赖真实短 sleep（约 +2 s 测试耗时），后续可注入假单调时钟；
6. 真实采集是同步阻塞，`stop_event` 只能在 HTTP 请求返回后的检查点生效。
