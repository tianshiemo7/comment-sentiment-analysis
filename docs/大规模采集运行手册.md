# 大规模采集运行手册（B 站评论，2026-10-17）

> 目标：**正确性/完整性优先，速度次要**。在单进程、串行、限速的前提下，把
> 「批量清单 → 断点续采 → 全量合并 → 数据质检」做成可反复重跑的流程。
>
> 两种使用方式：**Web 界面**（推荐；可视化、分步控制，适合单个/少量 BV 与参数试跑）与
> **CLI 批量清单**（适合上千个视频的长跑、断点续采与合并导出）。两者共用同一套爬虫实现、
> 限速语义与合规要求。
>
> 相关实现：`src/crawler/bilibili.py`（采集/断点/合并）、`tests/test_crawler.py`
> （含 30 视频 × 3 页 × 20 条离线规模测试）、`src/crawler/README.md`。

## 一、先决条件：登录态

匿名模式的可见评论量**随接口策略/风控波动**：实测同一视频 2 页约 39 条，但继续翻页可到
**200+ 条/11 页仍未结束**（不代表任何视频都能翻到全量，也不保证稳定）。要采完整规模，
必须先配置登录态；`--require-login` 用于在未登录时直接失败，避免白跑。

```bash
# 方式一：完整 Cookie（浏览器开发者工具复制，注意不要提交到仓库）
export BILI_COOKIE='SESSDATA=...; bili_jct=...; DedeUserID=...'

# 方式二：单个变量
export BILI_SESSDATA='...'
export BILI_BILI_JCT='...'
export BILI_DEDEUSERID='...'
```

采集前检查：

```bash
python -m src.crawler.bilibili --check-login
# 已登录 → 退出码 0；未登录 → 退出码 2
```

代码不会内置任何凭据；Cookie 只从环境变量读取，`--check-login` 不会落盘。
（Web 界面方式推荐用「登录 B 站账号（弹出登录窗口）」：由后端在本机弹浏览器、人完成登录后
自动保存 Cookie；也可手动粘贴 Cookie。凭据只存服务端 `outputs/settings.json`，见第二节。）

**登录态主要提升的是「可见量/完整性/稳定性」，不是单请求速度**：

- 匿名：可见页数/评论数随接口策略波动，深层分页可能中途结束；
- 登录：更可能翻到完整评论与楼中楼，深层分页更稳定；单页 `ps=50` 在登录态下
  可能真正返回接近 50 条（需账号实测，匿名实测只到 29）；
- **不提升**：仍保持 2.5 秒/请求的合规限速，不会用账号绕过风控或并发抓取。

## 二、Web 界面方式（推荐）

> 适合：单个 / 少量 BV、需要可视化进度、想先试参数再放大规模；
> 批量清单长跑仍推荐 CLI（第三~五节）。两种方式共用同一套爬虫实现与限速语义。

### 1. 启动服务

```bash
# 后端（仓库根目录）
python -m uvicorn src.inference.app:app --host 0.0.0.0 --port 8000

# 前端（另一个终端）
cd frontend
npm install
npm run dev        # 打开 http://localhost:3000
```

两个服务需同时运行，前端通过 Vite 代理访问 `/api`；详细步骤见 README 第四节。

### 2. 配置账号（左上角齿轮图标按钮「设置」）

左上角实际是**齿轮图标按钮**（`aria-label="设置"`，旁边显示账号模式徽标：匿名 / 已登录昵称），
点击即打开「系统设置」弹窗。

**推荐：人工登录窗口（不自动破解验证码）**

1. 设置弹窗「账号」点「登录 B 站账号（弹出登录窗口）」；
2. 后端在**运行服务的那台电脑的桌面**上打开真实浏览器窗口（本地课程项目即本机），
   并打开 B 站登录页；如果后端跑在远程服务器 / 容器里，需要到服务器桌面操作；
3. 由**人**在窗口里扫码，或输入账号密码 + 验证码完成登录；等待期间**不要关闭窗口**，
   超过 300 秒会超时；
4. 后端自动捕获 `SESSDATA` 并写入 `outputs/settings.json`，前端轮询显示「已登录：昵称」。

人工登录窗口需要可选依赖：`pip install playwright` + `python -m playwright install chromium`
（Windows 已装 Edge 可直接用系统 Edge）。未安装时点按钮返回 **503 + 安装指引**，
此时改用手动 Cookie，其它功能不受影响。

**高级兜底：手动粘贴 Cookie**

- 浏览器登录 B 站 → `F12` → Application / 应用 → Cookie → `https://www.bilibili.com` →
  复制 `SESSDATA`（或完整 Cookie 串）→ 设置页「高级：手动粘贴 Cookie」→ 检查登录状态 → 保存；
- 凭据只存服务端 `outputs/settings.json`（可用 `CSA_SETTINGS_PATH` 覆盖；已被 `.gitignore`
  忽略，**切勿提交**）；接口只返回 `has_cookie` / `masked_cookie`，日志与错误脱敏；
- 合规：只用自己的账号（建议小号）；Cookie 等同登录态，勿分享；采集遵守 robots 与限速
  （默认 2.5 秒/请求，硬性下限 2 秒），不绕过风控、不并发抓取，仅用于课程学习与研究。

### 3. 配置采集参数与自动流程

Web 的采集参数在「设置 → 采集参数」保存为默认值，提交任务时还会在「爬虫参数」弹窗逐次确认。
UI 参数与 CLI 选项一一对应：

| UI 参数（设置页 / 弹窗） | settings 字段 | CLI 选项 | 默认值 / 范围（设置页） |
| --- | --- | --- | --- |
| 真实采集开关 | `crawl.real_crawl` | —（CLI 始终真实采集） | 默认开；关=占位数据（离线演示） |
| 最多采集页数（一级评论） | `crawl.max_pages` | `--max-pages` | 默认 1；`0~50`，0=不限 |
| 楼中楼最多页数 | `crawl.max_sub_pages` | `--max-sub-pages` | 默认 1；`0~20`，0=不限 |
| 每页条数 | `crawl.page_size` | `--page-size` | 默认 20；`1~50` |
| 采集楼中楼 | `crawl.include_replies` | `--include-replies` | 默认关 |
| 排序方式 | `crawl.sort_mode` | `--mode` | 默认 `time`；`time` / `hot` |
| 最多新增评论数 | `crawl.max_items` | `--max-items` | 默认 200；`≥0`，0=不限 |
| 请求间隔（秒） | `crawl.delay_seconds` | `--delay` | 默认 2.5；`2.0~60`（合规下限 2） |
| 请求超时（秒） | `crawl.timeout_seconds` | `--timeout` | 默认 15；`>0` |
| 要求登录态 | `crawl.require_login` | `--require-login` | 默认关 |
| 初始化 buvid | `crawl.init_buvid` | `--init-buvid` | 默认关（开启会收紧匿名可见量） |

> 设置页默认值比 CLI 更保守（1 页一级 + 1 页楼中楼 + 最多 200 条），适合先小规模试跑；
> `max_pages=0` / `max_sub_pages=0` 表示不限（直到接口自然结束），与 CLI 一致。

「自动流程」两个开关默认关闭（`auto_clean` / `auto_analyze`）：开启后采集完成自动清洗、
清洗完成自动分析，不再停在「待清洗 / 待分析」。

### 4. 提交任务与分步执行

1. 顶部输入 BV 号 → 点「开始分析」；
2. 在「爬虫参数」弹窗确认本次参数（预填设置页默认值，可覆盖）→「确认」提交；
3. 任务 `queued → crawling → crawled（待清洗）`；点「开始清洗」；
4. `queued → processing（清洗）→ cleaned（待分析）`；点「开始分析」；
5. `queued → processing（情感推理 → 统计分析）→ completed`，在右侧查看图表、词云与评论；
6. 若在设置页打开「自动清洗 / 自动分析」，对应阶段不再暂停、自动连续跑完。

> Web 界面一次只提交一个 BV 任务；批量清单、断点续采、合并导出仍用 CLI。
> 任务中间产物在 `outputs/videos/<bvid>/`（`crawl.json` / `clean.json` / `analyze.json`，
> 其中 `analyze.json` 是逐条规则预测结果、供审计），详情在
> `outputs/videos/<bvid>.json`；失败可「重试」，等待态可随时继续。

### 5. 与 CLI 的关系

- **CLI 仍可独立使用**，不读 `outputs/settings.json`：命令行参数 + `BILI_*` /
  `VIDEO_CRAWL_*` 环境变量照旧生效（第一、三~九节）；
- **优先级**：任务级 `settings`（Web 弹窗确认）**优先于** `VIDEO_REAL_CRAWL` /
  `VIDEO_CRAWL_*` 环境变量；带 `settings` 的 Web 任务不受这些环境变量影响；
- **推荐工作流**：先用 Web 对 1 个 BV 试参数（数据量、耗时、可采深度）→ 确认后把同一套参数
  放大到 CLI 清单批量跑（`--max-pages` / `--max-sub-pages` / `--page-size` / `--include-replies`
  / `--mode` / `--max-items` / `--delay` / `--timeout` / `--require-login` / `--init-buvid`），
  参数语义完全一致；
- Web 的 Cookie 保存在设置文件里仅供 Web 任务使用；CLI 仍需 `BILI_COOKIE` / `BILI_SESSDATA`
  环境变量（或运行 `--check-login` 前导出）。

## 三、准备 BV 清单

一行一个，支持 `#` 注释、空行、完整视频 URL、`BV...,备注` 行内写法：

```text
# data/raw/bvids.txt
BV1GJ411x7h7
https://www.bilibili.com/video/BV1xx411c7mD
# 注释行会被跳过
```

同一 BV 重复出现会自动去重；非法行会进入报告的错误列表，但**不会中断整批**。

## 四、大批量采集命令

```bash
# 推荐：清单文件 + 不限页数 + 登录 + 楼中楼 + 日志 + 合并导出
python -m src.crawler.bilibili \
    --bvid-file data/raw/bvids.txt \
    --max-pages 0 \
    --max-sub-pages 0 \
    --include-replies \
    --require-login \
    --delay 2.5 \
    --out-dir data/raw \
    --log-file outputs/logs/crawl_batch.log \
    --merge-output data/raw/all_comments.csv
```

关键参数：

| 参数 | 作用 |
| --- | --- |
| `--max-pages 0` | 一级评论不限页数，直到接口 `is_end` |
| `--max-sub-pages 0` | 楼中楼不限页数，直到该根评论自然结束 |
| `--page-size 50` | 一级评论每页请求条数（`ps`，1~50；默认 20）。**会写进断点**，中途修改需 `--reset-state` |
| `--skip-finished`（默认） | 已完成视频**零请求跳过**，重跑清单只补未完成项 |
| `--rescan-finished` | 强制重扫已完成视频（CSV 仍按 rpid 去重） |
| `--require-login` | 未登录直接失败，避免匿名模式白跑 |
| `--merge-output` | 采集结束后流式合并所有视频 CSV |
| `--merge-dedupe` | 合并时跨文件按 rpid 去重（更耗内存） |
| `--max-seconds` | 单视频时间预算（0=不限）；到时保存断点，下次续采 |
| `--log-file` | 长跑日志（含每页进度、风控、错误） |
| `--quiet` | 只保留告警/错误与最终汇总 |

## 五、断点与重跑语义

- 每个视频：`data/raw/<BV>_comments.csv` + `data/raw/.checkpoints/<BV>.json`；
- 页级 offset / `pages_done` / `sub_done` 每页落盘（原子替换）；
- 已完成（`finished=true` 且 CSV 非空）的视频重跑时**不发任何请求**；
- 中断后直接重跑同一命令即可：已完成跳过，未完成从断点继续；
- 风控（412/-352/429）自动冷却+刷新 WBI+重试；重试耗尽则安全停止，已采数据保留；
- 同一 BV 的 CSV 按 rpid 去重，重复运行不会重复写。

## 六、完整性检查与合并

```bash
# 只合并（不采集）
python -m src.crawler.bilibili \
    --merge-output data/raw/all_comments.csv \
    --out-dir data/raw \
    --merge-lenient

# 校验：行数 / 视频数 / 唯一 rpid / 空文本 / 标签分布（下游管线自动做清洗）
python - <<'PY'
import csv, collections
rows = list(csv.DictReader(open('data/raw/all_comments.csv', encoding='utf-8-sig')))
print('rows', len(rows), 'videos', len({r['bvid'] for r in rows}),
      'unique rpid', len({r['rpid'] for r in rows}),
      'empty text', sum(1 for r in rows if not r['text'].strip()))
PY
```

合并是**流式**的：内存占用与文件数量无关；默认不按 rpid 去重（每视频文件内部已去重，
B 站 rpid 全局唯一），需要时加 `--merge-dedupe`。

## 七、容量与时间估算（速度次要）

默认 2.5 秒/请求（合规下限 2 秒，CLI 强制），单进程串行。单请求实测网络延迟约
0.13~0.33 秒，因此**每页约 2.6~2.8 秒**。

### 3,000 条一级评论的视频（示例）

| 页大小 | 页数 | 最低耗时（2.5s/页） | 最低耗时（2.0s/页，合规下限） |
| --- | --- | --- | --- |
| 20 条/页（默认） | 150 | ≈ 6.7 分钟 | ≈ 5.3 分钟 |
| 29 条/页（匿名实测 `ps=50` 返回 29） | 104 | ≈ 4.6 分钟 | ≈ 3.7 分钟 |
| 50 条/页（登录态理论值，需账号实测） | 60 | ≈ 2.7 分钟 | ≈ 2.1 分钟 |

> 上表只是**一级评论**；如果视频还有楼中楼，请求数会显著增加。

若该视频 3,000 条是「一级 + 楼中楼」的总量，且 20% 的根评论有回复、平均每条根评论
需要 1~2 页楼中楼，则总请求数约为：

| 场景 | 一级请求 | 楼中楼请求 | 总耗时（2.5s/页） |
| --- | --- | --- | --- |
| 3k 一级，无楼中楼 | 150 | 0 | ≈ 6.7 分钟 |
| 3k 一级，20% 有 1 页回复 | 150 | 120 | ≈ 12 分钟 |
| 3k 一级，20% 有 2 页回复 | 150 | 240 | ≈ 17 分钟 |
| 3k 总量（一级 2.5k + 楼中楼 0.5k） | 125 | ≈ 25 | ≈ 6.7 分钟 |

计算式：总请求 ≈ `ceil(一级数 / 页大小) + Σ ceil(每条根评论回复数 / 20)`；
实际耗时为 `请求数 × (delay + 网络延迟)`，另加少量重试/风控冷却。

大规模清单：

| 规模 | 请求数（约，20 条/页） | 最低耗时（约，2.5s/页） |
| --- | --- | --- |
| 100 个视频 × 50 页（10 万条，无楼中楼） | 5000 | ≥ 3.5 小时 |
| 1000 个视频 × 20 页（40 万条，无楼中楼） | 2 万 | ≥ 14 小时 |

- 开启楼中楼会显著增加请求数（每条有回复的根评论最多再翻 N 页）；
- 建议用 `--max-seconds` 给单视频设上限，分多天/多轮跑；
- 磁盘：按 40 万条估算约 150~250 MB（含 CSV 与断点，取决于文本长度）；
- 速度不是目标，**不要降低 `--delay`**，也不要并发抓取（合规与稳定性优先）。

## 八、失败处理

| 现象 | 处理 |
| --- | --- |
| 未登录 / 登录态失效（-101） | 重新导出 Cookie，`--check-login` 确认 |
| 风控（412/-352/429） | 程序自动冷却重试；持续失败会安全停止，隔一段时间重跑 |
| 网络中断 / Ctrl+C | 已采 CSV 与断点保留；重跑同一命令续采 |
| 部分视频评论关闭/不存在 | 记为 error 但继续整批；报告 `failed_count` |
| 合并时坏文件 | `--merge-lenient` 跳过并记录 |

## 九、已验证能力（2026-10-17）

- 单元测试：`tests/test_crawler.py` **81 条**（含无限页、零请求续采、单视频意外错误不中断整批、30 视频 × 3 页 ×
  20 条离线规模测试、批量合并、来源聚合、登录态/Cookie 解析）；
- 离线规模测试：500 视频 × 3 页 × 20 条 = **30,000 条 / 500 个 CSV**，假客户端采集 3.15 s，
  流式合并 30,000 行（3.43 MB）16.22 s；重跑清单 **500 个全部零请求跳过（12.98 s）**；
- 真实联网已实测：`--check-login`（匿名返回未登录）、`--bvid-file` + 非法行容错、
  已完成断点零请求跳过（`requests=0`）、`--merge-output` 合并 59 行；
- 匿名深层翻页：本机匿名实测同一视频连续翻到 **19 页 / 577 条仍未结束**（不同视频/时段
  可能不同），说明匿名并非固定 3~39 条，但完整规模仍建议登录态；
- **未验证**：真实登录态下的深层分页/楼中楼全量（需要使用者自行提供 Cookie），
  以及超大规模（10 万+）实际跑批——架构已按此设计，建议先小批量验证再放大。
